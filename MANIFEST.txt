MODIFIED FILES
──────────────────────────────
src/components/pitch/SlideRenderer.jsx
  The actual fix for the desktop vertical-space issue. The right-side visual
  column was `justifyContent: center`, which shrink-wraps its content instead
  of letting it fill the column — that's why the shop mockup looked short
  once we added scrolling. Removed that from both the generic layout (used
  by 4 of 5 themes) and Brutalist's custom layout. Short mockups (hero,
  workflow, etc.) are unaffected — they still center themselves, just via a
  wrapper that now also knows how to stretch when a mockup asks it to.

src/components/pitch/visuals/DeviceFrame.jsx
  Added an opt-in `fill` prop. When true (Customer, Merchant), the frame
  stretches to use all available height in the slide and only scrolls
  internally if content still doesn't fit — so on desktop, in Present mode,
  it now actually uses the vertical room it has. When false (default —
  every other mockup), nothing changes, they stay exactly as compact and
  centered as before.

src/components/pitch/visuals/demoVisuals.jsx
  - Removed the fixed maxHeight caps on Customer's grid/cart and Merchant's
    Orders/Products/Customers lists — DeviceFrame handles the scroll as a
    whole now, so these just flow naturally.
  - "▶ Live now" on the last slide is a real link to peakenterprise.ca now
    (opens in a new tab).
  - Added a real, offline-generated QR code next to it, same link — no
    external API call, so it works even on bad venue wifi.
  - Product/theme data now imported from emberMoss.js instead of being
    defined inline (see above).

package.json / package-lock.json
  Added react-qr-code (~3kb, zero dependencies, pure SVG — no canvas, no
  external network call at render time). Ran `npm audit` after adding it:
  the vulnerabilities npm reports are all pre-existing, from jsPDF, Vite,
  react-router, etc. — none new from this package.
